# nibbanahelp — the private pillar
*Status: REFERENCE. Per-repo reference: role, gate, honest state. (2026-11-14.)*

## Role

A day-by-day diary of attaining nibbāna — real entries, real tensions, and an
AI relay that gets better as the database grows. It is the **only private
layer** in the estate and the source for the endgame recipes (diary →
personalised teaching → audio → video → book).

## The invariants (non-negotiable)

- **Private by construction.** Diary bodies, keys, and vectors are never
  exposed in any public asset, archive, or crawler-facing file.
- **Consent per use, revocable.** Any material leaving the private layer
  requires explicit, scoped consent from the owner.
- **No auto-publish, ever.** The relay never advises; it relays lived
  experience with provenance, tiered canon → lineage → lived → trika.
- **VOICE RULE.** Public exports are headers + status only, never body text.

## What it contributes to the estate (read-only)

- Public **tensions** export (headers + status) feeds trika-x's crux queue.
- The endgame recipe family (R1 diary→essay, R2 audio, R3 video, R7 year-review
  book, R8 poem book) is specified in trika-x `ENDGAME-RECIPES.md`; every one
  is owner-gated and unbuilt until consent opens it.

## What never happens

The scraper/readers here never read diary bodies. No endpoint that serves
private material is listed publicly (the private relay was removed from the
svread public surface on 2026-11-14). If a public file ever names a private
path, that is a defect, not a feature.

## Gate

Repo-local (`AGENTS.md`, `HANDOVER.md`); the lane owns its own integrity
checks. From the estate's side the only test is: does anything private leak
into a public artifact? (The svread `no private material in crawler-facing
files` test is the enforcement point.)
